# 关注会话工作台

## 1.2.3 物理键识别与只读诊断

按 event.code 优先归一化物理键，修正 Mac Option/Alt 将 KeyM 变成 µ、以及本地化分号等 event.key 与键位不一致时无法匹配的缺陷；没有 code 的环境继续使用受控 key 回退，输入法/Dead/Process 仍不触发。Ctrl+B 的原生放行与旧配置迁移保留。

快捷键设置中新增只读「按键诊断」：先关闭设置测试，再打开并刷新，查看配置就绪状态、最近 8 次组合键/前缀步骤的物理 code、匹配结果、作用域及暂停/保护等理由；不记录普通输入正文，不写盘、不修改配置。前缀用法：按 Ctrl+; 后松开 Ctrl，再在 1.2 秒内按下一键。设置浮窗打开时工作台快捷键按设计暂停。

该版本修复的是可复现的识别缺陷，尚不能认定用户实际无响应的全部根因已消除。原生 Desktop 对主 frame 未匹配组合键会在 preventDefault 前返回，不能归因于普遍吞掉未知快捷键：见 [同版本 keyboard.ts](https://raw.githubusercontent.com/deepseek-ai/deepseek-harness/dsh-v0.2.2-rc.3/apps/desktop/src/keyboard.ts)。未引入原生桥接或改变现有键位配置，真实现场需再验证。

## 1.2.2 前缀避让 DSH

默认公共前缀改为 Ctrl+;，Ctrl+B 不再允许配置，也不在前缀等待或录制时拦截。旧有效配置中公共前缀为 Ctrl+B 的，在新版加载时迁移到 Ctrl+;；Prefix 序列和以旧前缀开头的固定序列随迁移，启用状态、作用域及其它配置不变。迁移若与已有固定序列冲突，则安全禁用配置，需在设置中重新配置。读取迁移不主动写盘，后续成功保存状态时持久化；不清空关注或布局。其它有效自定义前缀不替换。

已核对部分同版本原生键位声明，未发现 Ctrl+; 占用；未证明操作系统、输入法、用户自定义覆盖和全部 Web 环境均无冲突。本插件仍使用原有 DOM 适配器，不冒充原生 shortcut registry 的全平台许可。此次仅修正前缀，不宣称解决右侧栏卡死，亦不自动重新启用插件。

## 1.2.1 设置浮窗

「⌨ 快捷键」改为工作台内的居中浮窗，不再挤占分屏布局，也不会重挂原生会话。浮窗内独立滚动，背景工作台暂不可操作；支持关闭按钮、遮罩点击及 Esc。未保存修改仍先提示放弃或继续编辑；录制时 Esc 只取消录制。Tab 保持在浮窗内，关闭后尽量恢复原控件焦点。此浮窗不是 Desktop 独立窗口。


## 1.2.0 快捷键与设置

工作台工具栏新增「⌨ 快捷键」。支持总开关、单项启停、局内/局外独立勾选、文本改绑、组合键/两步序列录制、筛选、保存、取消和恢复默认。编辑和录制只修改草稿，服务器确认落盘后才应用；并发配置变更会提示重新载入，停用不会清空键位。

默认快捷键（前缀是先按 Ctrl+; 松开，再按下一键）：

- Ctrl+方向键，或前缀后 h/j/k/l：空间切窗，边界不绕回。
- 前缀后 1～4：编号选窗；只选择当前布局允许的窗格。
- 前缀后 ;：上一窗格；z：最大化/恢复；/：搜索关注列表；i：聚焦当前原生输入。
- Ctrl+Alt+M：显示/聚焦工作台，明确同时启用局内和局外。

其它默认绑定仅局内。局外限于当前 DSH 页面，不是系统全局热键。可将同一绑定同时勾选局内和局外；省略作用域永远默认为局内。配置中 Prefix H 等跟随公共前缀，Ctrl+K X 则是固定两步序列，备选键以 | 分隔。

编辑区保留 Ctrl+方向键；输入法组词不触发快捷键。默认 Ctrl+Alt+M 在编辑区也可用；其它单步改绑默认不抢编辑键。设置页打开或录制时暂停工作台快捷键。发送、停止及常用复制/粘贴/撤销/浏览器保留键不能改绑；前缀本身会占用选定组合键，可修改。macOS 等系统可能先截获 Ctrl+方向键，请使用前缀备用方案。

焦点切换尽量恢复同一仍挂载输入区的光标/选区；最大化导致原生视图重挂时不承诺恢复旧 DOM 选区。同一页面保存成功立即应用；其它已打开页面在获得焦点或约 15 秒配置刷新后同步。真实原生输入、系统键冲突和多窗口行为仍需实际 GUI 验收。


1.1.0：分屏复用 DSH 内置 `conversation.content`，使用 embedded 形态，保留原生输入、工具卡片、Markdown、附件及审批。用户已明确取消只读限制。标题采用与原生列表相同的 `displayTitle`，加大加粗并允许两行；不再使用截断 session ID 冒充名称。

## 使用

1. 在会话标题旁点击星标，或在「关注会话」工作台批量搜索添加已有会话。
2. 卡片模式提供轻量摘要，每组最多 12 个实时预览；双屏/四宫格中每个可见窗格挂载原生 Conversation。
3. 先点选窗格，再点左侧关注项，或拖入窗格；相同会话不重复占据多个窗格。
4. 窗格内可以使用原生输入框、批准等交互。输入、停止和批准的含义与原会话相同，不是对任务的只读副本。
5. 分隔线可拖动、双击复位或键盘调整；可最大化/恢复，亦可打开原会话，通过「↶ 工作台」返回。
6. 移出分屏只移除展示，不取消关注、不停止任务。取消关注提供 8 秒撤销。

## 实现与边界

- 工作台仅拥有关注和布局；不移动原页面 DOM、不嵌 iframe、不全局替换原生 Composer/View，也不自己解析分屏正文。
- 每个可见窗格持有自己的 SessionReference，传入 SessionProvider；原生子组件在该作用域调用 conversation.content Factory。不是给 Provider 传 ID 字符串。
- 不同会话作用域隔离；同一会话在不同入口的草稿/视图遵循原生共享语义，不创建独立副本。
- 切换卡片模式、隐藏/替换窗格或卸载会释放窗格引用。历史加载、跟随、滚动和工具展示使用原生实现；重新挂载后的原生滚动恢复仍需真实 GUI 验收。
- 标题、搜索、卡片、关注列表使用同一标题解析规则。没有标题时显示“未命名会话”。
- 卡片仍采用安全文本摘要；分屏的 Markdown、图片、工具详情、推理折叠等完全遵循原生组件与现有设置。
- 关注、排序、布局、窗格绑定、比例、已读水位保存在当前配置档；不额外保存消息正文或模型凭据。
- 保存采用修订号检查和串行落盘；GET 读取为 buffered，POST 保存独立 streaming 路由，均限制为当前认证所有者。
- 展示本身不自动发送提示、批准请求或停止任务；原生交互仅响应用户操作。用户操作可能调用模型或更改会话状态。
- 旧格式会话仍需在原会话明确处理升级。没有后台通知、自动摘要、批量发送或任意嵌套分屏。
- 原生挂载失败会显示错误及重试/打开原会话入口，不以纯文本假装原生渲染成功。

## 开发

```sh
npm ci --ignore-scripts --cache .npm-cache
npm run build
npm run check
npm test
npm pack --ignore-scripts
```

无第三方运行时依赖，原生 UI 由当前 DSH 提供。官方后端、HTTP bridge 和 SlotCore 开发依赖固定为 0.2.2-rc.3。客户端由构建脚本生成，不直接编辑生成文件。详见 `docs/NATIVE_RENDERING.md` 与 `docs/VALIDATION.md`；接口检查和测试通过不等于已完成当前登录页的全动线视觉验收。
