# 知识树 (Knowledge Tree)

DeepSeek Harness Web UI 的知识梳理插件：**先列举、再归类、最后成树**，三个阶段锁死顺序，
侧栏多一个图标，点开就是整页的知识树工作台。

## 三个阶段

顺序是故意锁死的，每个阶段解决一种失败：

| 阶段 | 你要做的 | 系统替你挡的 |
| --- | --- | --- |
| ① 列举 | 一条一条写：标题必填，内容可选 | 边写边分类，清单越写越少 |
| ② 归类 | 在自动排布的白板上把卡片拖到目标卡片上 | 手工摆版式，摆完没力气判断归属 |
| ③ 成树 | 只做裁决：改名、调顺序、补内容、导出 | 环、过宽、关联，系统检查出来 |

出门条件：列举至少 2 张；归类必须没有「待整理」；成树要处理完结构检查项。

## 知识卡片

一张卡 = **标题 + 内容 + 可选的一张配图**：

- 标题必填、一句话，是树节点的名字；内容可选，放解释、例子、来源。
- **图片**：粘贴截图（展开卡片后 Ctrl/⌘+V）、把图片拖到卡片上、或点「＋ 图片」选文件；
  自动压到长边 ≤1280px、WebP、≤420KB，展开后显示缩略图，点图看大图，可更换 / 移除。
- **默认收起，只显示标题**；点卡片展开看内容，再点收起。
- 收起态也显示状态与归属：`待整理`、`N 个子项`、`N 个关联`、`→ 主题名`、`顶层主题`。
- 展开后可改归属、添加关联、设为顶层主题、取消归类。
- **删除要二次确认**：点删除按钮，它原地变成「取消 / 删除」两个小按钮（不用移鼠标去找弹框），
  只有点「删除」才生效；点「取消」、点别处或按 Esc 都不动数据，删完还能用「撤销」恢复。

## 归类：自动布局的白板

所有卡片落在同一块白板上，**位置由插件排，你只负责连接**：

- **引导语可编辑**：列举阶段顶部「引导」旁的「编辑」，可以增删改提示语、恢复内置的 12 条；
  改完点「换一个」在自定义列表里轮换，只存本机。
- **新建主题**：几条知识共同的上位主题还不存在时，点「＋ 新建主题」，创建后再把它们拖进去。
  主题创建即顶层主题，不进入待整理。
- **补一条知识**：归类时就地补录，落在「待整理」。
- 把卡片拖到另一张卡上 = 归入它；**按住 Shift** 拖放 = 添加关联（同一张卡在另一主题下再出现一次，不是复制）。
- **拖放预告**：拖动时提示条显示「将「A」归入「B」」，目标卡片高亮。
- **顶层有专门投放区**：拖到「设为顶层主题」区域才设为顶层；拖到画布空白处不会修改任何数据，并提示原因。
- **三种状态**：待整理（虚线 + 角标）/ 顶层主题 / 已归入上级（`→ 主题名`），
  顶部摘要 `待整理 / 顶层主题 / 已归入上级` 的数字都来自真实数据。
- 只有「待整理 0」时才能进入下一阶段；「其余设为顶层主题」可一键清空。
- 把节点挂到自己的子孙下会被拒绝（防环）；每步可撤销（50 步）。
- 卡片展开区有「改归属…」「添加关联…」「设为顶层主题」「取消归类」，对话框可搜索，
  是键盘 / 触屏的等价入口。

## 成树

- **结构检查**：主层级有环才报错（可一键断开）；额外交联作为**关联 N 处**单独列出（改为主归属 / 移除关联）；
  多个顶层主题与过宽分支只提示。
- 只有真的检查过且无环才显示「结构检查通过」；「可以导出」单独说明，不暗示内容或分类已被确认。
- **大纲编辑**：点整行展开 / 收起内容（按钮、输入框除外），可改标题、编辑内容、折叠子项、加子项、
  删除（子项上提）、同级上移 / 下移、拖动改父。**树形预览**：只读，看整体形状。
- **树名**是文档名，不是根节点：有独立标签与说明，只改名称不影响结构，导出文件名也用它。
- **保存状态**：页脚与工具栏显示「已保存到本机 · HH:MM」（只在写入成功后出现）；
  写入失败显示「未保存：浏览器拒绝写入」。
- 顶部「上一步」在成树阶段是「回到归类（改归属）」，全流程只有这一条回到结构编辑的路径。

## 导出

右上角「导出」按有没有配图分两种组合：

- **没有图片**：Markdown 大纲（`- 标题`，内容为 `> 引用` 行，关联为 `↪ 另关联：…`）+ 单个 HTML 文件。
- **有图片**：ZIP（`tree.md` + `images/`，Markdown 里用相对路径引用）+ 单个 HTML 文件（图片内嵌，单文件可看）。

两种情况下都另有 Mermaid `mindmap`（只含标题）、JSON 备份（含图片，可再导入并按 id 合并）、
复制纯文本大纲（只含标题）。导出包含全部卡片、关系与图片，**不受折叠或当前视图影响**。
成树阶段另有「复制 Markdown」一键按钮（纯文本，不含图片）。

## GitHub 同步（v2.0）

本地多棵知识树与一个 GitHub 远端知识库共存。左侧「新建本地树」填写名称后创建独立文档；双击本地树名称可直接重命名；右键名称打开「重命名 / 删除」菜单（平时隐藏，点击外部或 Esc 关闭，删除仍需二次确认）。键盘可用 F2 重命名、Shift+F10 打开菜单。名称 1–60 个字符，前后空白自动去除，不改变树 ID、卡片或同步关联，也不会自动上传。点击远端树只读浏览，右侧与本地编辑器并排显示，不需要先 Pull。

1. 打开「GitHub 配置」，填写仓库所有者、仓库名、已有分支、目录（默认 `knowledge-trees`）。仓库与分支必须预先创建，空仓库请先创建 README 提交。
2. 提供仅授权该仓库的 fine-grained PAT：查看需要 Contents 读取权限，Push 需要 Contents 读写权限。**此处输入的 PAT 仅在 Host 内存中保留，插件重载或应用重启后需要重填**；也可在启动 Host 前设置 `KNOWLEDGE_TREE_GITHUB_TOKEN`。不会保存到浏览器持久存储、配置文件或知识树导出文件。
3. 「手动刷新远端目录」列出树；选中即并排查看。网络失败时可显示明确标注时间的缓存。
4. 「推送当前本地树…」确认提交说明后，仅上传当前文档。推送期间继续编辑的内容留在本地，不会被这次提交覆盖或顺带上传。
5. 「拉取当前远端树」首次创建本地副本；已有同步关联时，仅在没有本地未推送修改的情况下更新，并提前创建恢复快照。双方有修改则停止，不强推、不自动合并，可把远端另存为独立本地树。
6. 删除本地树不会删除 GitHub 内容。快照恢复创建独立本地副本，原树不变。

GitHub 存储格式：`<目录>/<稳定treeId>/tree.json` 为权威数据，`tree.md` 是供 GitHub 阅读的生成文件，图片保存为 `assets/<sha256>.<扩展名>`。一次 Push 创建一个包含所有变更的 commit，再以 `force:false` 更新分支；并发更新失败时不会覆盖他人提交。只操作当前树的受管文件，不修改仓库其他文件。手工改 Markdown 不会反向更新 JSON。

**隐私**：默认不发起 GitHub 数据请求，只有主动刷新、查看、Pull 或 Push 才访问远端。公开仓库中的正文和图片公开可见，请勿上传私密资料。展开状态和自定义引导语不上传。

## 数据

- 本地文档、UI 状态、同步基线、远端缓存、恢复快照保存在当前浏览器的 IndexedDB `dsh-knowledge-tree-library`，不是磁盘 Git 工作区。图片在本地仍为记录中的 data URL（第一版未拆 Blob）。容量由浏览器配额决定，不再受单个 localStorage 约 5MB 限制。
- 首次从旧 `dsh-knowledge-tree/v3`、`v2` 或 `v1` 迁移一棵本地树；数据、UI、引导语副本在一次事务内写入，**原 localStorage 键永不删除或覆盖**。损坏迁移报错并保留原数据，不用空树覆盖。
- 自定义引导语仍使用 `dsh-knowledge-tree:prompts/v1`（只存本机，不上传）；旧视图偏好保留。
- 非敏感仓库配置保存在 Host 的 `DSH_HOME/storages/knowledge-tree/<profile>.json`；Token 不写此文件。清除会话 PAT 不会移除环境变量凭据。
- 本地保存使用 revision CAS；另一个窗口更新同一棵树时拒绝旧版本覆盖。保存失败时保留当前页草稿并提示重试，关闭页面前请先解决错误或导出备份。

浏览器数据按 origin 隔离；更换 Host 端口、浏览器或设备可能访问不到旧 IndexedDB。GitHub 不是自动备份：换设备或清缓存前，请确认已 Push 或导出 JSON。

## 结构

| 文件 | 作用 |
| --- | --- |
| `package.json` | 包清单：`dsh.bundle.patch` + `dsh.client`（web，立即加载） |
| `cordis.patch.yml` | 插入 Host 行 `knowledge-tree` |
| `index.js`、`host-service.js` | Host 入口、已鉴权 API、配置与会话凭据 |
| `github-sync.js` | GitHub 原子提交、图片分离、严格校验与冲突保护 |
| `library.js`、`workspace-ui.js` | IndexedDB 资料库、多树导航与同步界面 |
| `build-client.mjs` | 将测试过的无依赖模块嵌入浏览器 bundle |
| `client.js` | 浏览器半：store、三阶段页面、白板自动布局、树视图、导出、i18n、样式 |
| `locale/en.json`, `locale/zh.json` | 插件管理器标题与描述 |
| `icon.svg` | 原创图标（树形节点） |
| `DESIGN.md` | 设计稿与决策记录（不随 bundle 发布） |

## 安装

通过 DSH 的 Plugin Manager 安装本目录（bundle），或在会话里由 Agent 执行
`plugin_manager install_bundle`，target 指向本目录绝对路径。安装后左侧栏出现知识树图标。

## 已知限制

- 拖动依赖 HTML5 drag-and-drop，触屏浏览器不触发；用卡片展开区的按钮等价操作。
- 白板不做手工摆放（那会退化成手工排版），也不用力导向（会漂移）；规则见 DESIGN 第 4 节。
- 树形预览只读；改归属统一回到归类白板。
- 同级排序用 ↑ / ↓ 按钮，不做拖拽插入位。
- 阶段切换会重置白板滚动位置；展开 / 折叠状态保留。
- 每张卡最多一张图；本地保存受 IndexedDB 配额限制，失败会保留内存草稿并提示，不能把提示当作已保存。
- 第一版仅一个仓库；手动同步、远端只读、无自动合并、无 PR 流程。适配器限制 500 棵远端树、5000 卡片/10000 关系、单文档 20MiB、单图 512KiB、图片合计 12MiB；递归目录被 GitHub 截断或超限时明确失败，不展示不完整列表。编辑器上传图片仍压缩到 ≤420KB。
- 同步状态采用内容哈希与共同基线，不以时间戳判断覆盖；目前没有卡片级冲突解决器。
- GIF 按原文件保存（≤420KB），更大的 GIF 会被拒绝；不做图片标注、裁剪或相册。
- 引导语是本地的可编辑列表（内置 12 条），不接模型追问；自定义列表只存本机，不随 JSON 导出。
- 英文界面为尽力而为的翻译，不作为硬性兼容要求；自定义引导语不按语言分存。
