# 知识树（Knowledge Tree）插件设计

- 状态：**插件 v2.0 GitHub 同步第一版**（2026-11-07）；原编辑器数据格式仍为 v3。
- 本文 1–11 节保留旧编辑器设计记录；存储/Host 架构已由第 12 节及 README 的 v2.0 说明取代。
- 现为 Host + Client bundle、IndexedDB 多文档、手动 GitHub API 同步、主题 token。

## 1. 定位

一句话：**先逼你把知道的倒出来，再在白板上把知识归到主题下，最后收成一棵树。**

三步各有各的防失败机制：

| 原则 | 阶段 | 防的失败 |
| --- | --- | --- |
| 只许倒，不许整理 | 列举 | 边写边分类，越写越少 |
| 位置系统排，人只做连接 | 归类 | 手工摆版式，摆完就没力气判断归属 |
| 系统做体检，人只拍板 | 成树 | 手动拗树形，最后放弃 |

## 2. 知识卡片

一张卡 = `标题` + `内容` + `可选的一张配图`：

- **标题**必填，一句话，≤ 120 字，是树节点显示的名字。
- **内容**可选，≤ 4000 字，放解释、例子、来源。
- **配图**（v3）：每张卡最多一张。入口三选一——展开后 Ctrl/⌘+V 粘贴、把图片拖到卡片、点「＋ 图片」。
  管线：长边压到 ≤1280px → WebP q0.8（超 420KB 再降 q0.55 / 缩 0.6）→ 仍超则拒绝。
  GIF 原样保存（≤420KB）。展开显示缩略图，点开 lightbox，可更换 / 移除。
- **默认收起**，只显示标题；点卡片展开内容，再点收起。
- 收起态也带两条信息：状态角标（待整理 / N 个子项 / N 个关联）与归属（`→ 主题名`、`顶层主题`、`待整理`）。
- 展开态多显示：完整归属、另关联的主题、内容正文、以及动作（改归属 / 添加关联 / 设为顶层主题 / 取消归类）。

## 3. 三个阶段是一个显式状态机

```text
① 列举 brainstorm ──▶ ② 归类 classify ──▶ ③ 成树 tree
   只增卡片            白板上拖拽定归属       体检收束 + 排布 + 导出
```

- 顶部常驻阶段条，**不可点击跳转**；只有「上一步 / 下一步」，下一步在满足出门条件前禁用。
- 上一步的按钮文案随阶段变化：成树 → 「回到归类（改归属）」，归类 → 「回到列举」。
  全流程只有这一条回到编辑结构的导航路径，不再另设「编辑结构」按钮。
- 回退不丢数据；重新前进时按当前数据重新体检。
- 出门条件：
  - 列举 → 归类：卡片 ≥ 2 张。
  - 归类 → 成树：**没有「待整理」的卡片**（每张要么已归入某个主题，要么被显式设为顶层主题）。

### 3.1 列举：只增不改结构

- 标题输入 + 内容输入（内容可选），标题回车即加入，焦点留在标题框；内容框里 `Ctrl/⌘ + Enter` 也可提交。
- **IME 保护**：输入法组合候选词时按回车不会提交（`isComposing` / keyCode 229 双重判断）。
- 校验失败（标题为空）不清空输入，按钮保持禁用并提示。
- **引导**：顶部提示条从本地题库（12 条）轮播，纯前端，不调模型。
- **引导语可自定义**：顶部「编辑」打开列表，可增删改、可「恢复默认」；
  自定义后银行整体替换内置文案（保存到独立键 `dsh-knowledge-tree:prompts/v1`），
  「换一个」在自定义列表内轮换；空列表会被拒绝并提示恢复默认。
- 卡片默认收起，点开可改标题与内容、可删除；**不允许建立任何关系**。
- 页脚明确：开始归类后仍然可以回来补充卡片。

### 3.2 归类：自动布局的白板

所有卡片一次性落在同一块白板上，**位置由插件排，用户只负责连接**。

```text
┌ 归类   待整理 2 │ 顶层主题 1 │ 已归入上级 3        [＋新建主题][＋补一条知识][其余设为顶层主题] ┐
│ ┌ 设为顶层主题 —— 把卡片拖到这里 ─────────────────────────────────────────────┐          │
│ └──────────────────────────────────────────────────────────────────────────────┘          │
│ 提示：拖到卡片上 = 归入它；按住 Shift = 添加关联；拖到空白 = 什么都不发生          │
├──────────────────────────────────────────────────────────────────────────────────────────┤
│   ┌────────────┐        ┌────────────┐                                                  │
│   │ Tile 开发  │───────▶│ 标准解析   │                                                  │
│   │ 2 个子项   │        │ → Tile 开发│                                                  │
│   └────────────┘        └────────────┘                                                  │
│   ─ ─ 顶层 / 待整理 · 3 张 ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─                            │
│   ┌────────────┐  ┌────────────┐  ┌────────────┐                                        │
│   │ 渲染管线   │  │ 着色器编译 │  │ 批处理优化 │                                        │
│   │ 顶层主题   │  │ 待整理     │  │ 顶层主题   │                                        │
│   └────────────┘  └────────────┘  └────────────┘                                        │
└──────────────────────────────────────────────────────────────────────────────────────────┘
```

- **新建上位主题**（`＋ 新建主题`）：当几条知识共同的上位主题还不存在时，先建主题，再把这些卡片拖进去。
  主题创建即「顶层主题」，不进入待整理队列；输入框回车即建，Esc 关闭。
- **补一条知识**（`＋ 补一条知识`）：就地补录，落在「待整理」，补完可继续输入。
- **拖动建链**：卡片拖到另一张卡上 = 归入它；按住 **Shift** 拖放 = 添加关联（同一张卡在另一主题下再出现，不是副本）。
- **拖放预告**：拖动时提示条实时显示「将「A」归入「B」」「将「A」关联到「B」」「将「A」设为顶层主题」，目标卡片高亮。
- **顶层有明确投放区**：只有拖到「设为顶层主题」区域才会把卡片设为顶层；拖到画布空白处**不做任何修改**，并提示原因，
  避免「只是想挪一下却解除了归属」。
- **三种状态**用真实语义表达：
  - 待整理（虚线边框 + `待整理` 角标）：尚未决定放在哪里；
  - 顶层主题（`顶层主题`）：有意放在顶层；
  - 已归入上级（`→ 主题名`）：已指定父主题。
  顶部摘要 `待整理 / 顶层主题 / 已归入上级` 的数字全部来自卡片与链接的真实状态。
- **归属可见**：卡片收起态显示 `→ 主题名`；展开态显示完整归属与「另关联」；改归属后立即反映。
- **数字有单位**：`N 个子项`、`N 个关联`，不再是裸数字。
- **不跳步**：只有「待整理 0」时下一步才亮；「其余设为顶层主题」可一次性清空待整理。
- 环检测：把节点挂到自己的子孙下会被拒绝并提示。
- 每步可撤销（内存历史，最多 50 步），撤销同时恢复数据与画面。
- 触屏 / 键盘等价入口：卡片展开区的「改归属…」「添加关联…」「设为顶层主题」，
  对话框可搜索、Esc 取消；「改归属…」与 Shift 拖放语义相同，「添加关联…」与 Shift 拖放语义相同。

### 3.3 成树：系统体检，人拍板

体检分两类，**不再把合法关联当错误**：

| 检查 | 表达 |
| --- | --- |
| 主层级里有环（真实结构错误） | 红色 chip「环 N 处」+ 一键断开 |
| 一个节点有主归属 + 额外交联（合法） | 中性 chip「关联 N 处」+ 关联面板（改为主归属 / 移除关联） |
| 多个顶层主题 | 中性 chip「顶层主题 N 个」+ 提示如何收成一个根 |
| 单层过宽（某父 > 12 个子项） | 中性 chip「过宽 N 处」+ 提示 |

- 只有**真的跑过检查且无环**才显示「结构检查通过」；「可以导出」单独出现在导出说明里，
  不暗示内容或分类已经被确认。
- 视图：**大纲编辑**（可编辑）/ **树形预览**（只读）。预览页明确写出「预览只读」并指回编辑位置。
- 大纲编辑里可：改标题、展开看内容、编辑内容、折叠子项、加子项、删除（子项上提）、
  同级上移 / 下移、拖动改父（与归类白板同一语义）。
- **树名是文档名，不是根节点**：独立字段 + 标签 + 说明「只改文档名称，不影响结构；导出文件名也用它」，
  下方注明「下面是 N 个顶层主题」。
- **保存状态**：页脚与工具栏显示「已保存到本机 · HH:MM」（仅在写入成功后出现）；
  写入失败显示「未保存：浏览器拒绝写入」。导出成功另给 toast，与保存状态分开。
- **导出说明**：`可以导出 · 导出包含全部 N 张卡片与 M 条关系，不受折叠或隐藏影响`。

## 4. 自动布局规则（白板）

**分层树状自动排布，不采用力导向**——力导向会漂移、结果不可复现，节点一多「自动」就退化成
「手动整理」。具体规则：

1. 有子节点的卡片是树头：按深度分列（父在左，子逐层向右，列宽 236 + 46）。
2. 同一父节点下的子节点按录入顺序自上而下排列，间距 12。
3. 每棵子树占一段纵向带（子树高度 = 子节点高度之和，或自身高度取大），父节点在带内居中；
   多棵一级树自上而下叠放，间距 30。
4. 没有子节点的卡片（顶层主题与待整理，以及被环挡住无法挂入树里的卡片）排在下方网格区，每行 3 张。
5. 卡片收起 62px、展开 252px（标题栏 34 + 信息行 28 / 正文区），展开时布局重算，位置变化走 0.18s 过渡。
6. 边：主归属实线贝塞尔（较深的次级文字色），关联虚线直线（品牌色）。

## 5. 数据模型

存储键 `dsh-knowledge-tree/v3`（数据）、`dsh-knowledge-tree:ui/v2`（视图状态，不进导出）、
`dsh-knowledge-tree:prompts/v1`（自定义引导语，不进导出；缺省时用内置 12 条）。v3 未改数据结构。
v1（`text` + `note`）、v2（`title` + `content`）在首次加载时自动迁移到 v3；v3 只是在卡片上多一个 `image`。

```jsonc
{
  "version": 2,
  "stage": "classify",                  // brainstorm | classify | tree
  "title": "",                          // 文档名，空 = 默认「我的知识树」
  "cards": [
    {
      "id": "c_xxx",
      "title": "认知负荷理论",
      "content": "工作记忆一次只能处理 4±1 个组块",
      "image": {                          // v3；无图为 null
        "data": "data:image/webp;base64,…",
        "mime": "image/webp",
        "w": 1280,
        "h": 800
      },
      "placed": true,                   // 是否已定归属（顶层或已归入）
      "order": 0,
      "createdAt": 1762137600000
    }
  ],
  "links": [
    { "id": "l_xxx", "parentId": "c_a", "childId": "c_b", "primary": true }
  ],
  "updatedAt": 0
}
```

- `links` 是唯一事实来源；`primary` 标记主归属（每个子节点至多一条），其余为**关联**（同一条知识的另一处引用）。
- `placed` 区分「已定归属」与「待整理」——没有父链接但 `placed = true` 才是顶层主题。
- 白板坐标**不入库**，由第 4 节规则实时计算。
- UI 态：`{ view, collapsed: [id], expanded: [id], prompt }`。
- 校验：标题 ≤ 120、内容 ≤ 4000；加载时清洗坏数据（断链、自环、重复链接、多主父），
  `localStorage` 损坏时降级为空树并提示，不白屏。

## 6. 保存与导出

- 所有修改即时写入 `localStorage`；写入成功才把 `savedAt` 放进快照，界面据此显示「已保存」。
- 保存状态（页脚 + 成树工具栏）与导出反馈（toast）是两条独立信息。
- 导出按「有没有图」分两套（v3）：
  - 无图：Markdown（`- 标题`、内容为 `> 引用`、关联为 `↪ 另关联：…`）+ 单个 HTML。
  - 有图：ZIP（`tree.md` + `images/<id>.<ext>`，Markdown 用相对路径）+ 单个 HTML（图片内嵌）。
  - 两者都另有：Mermaid `mindmap`（只含标题）、JSON（含图片，可再导入并重新规范化）、纯文本大纲。
  ZIP 用内置 STORE 写入器（无依赖，`CompressionStream` 不需要）。
- 导出只读数据，与折叠 / 展开 / 当前视图无关（有测试覆盖）。
- 文件名取树名。

## 8. 实现要点

- `window.__ModuleLoader__.load({ id, factory(require) { … } })`，只 `require('react')`。
- store 与 todo-list 同模式：模块级数据 + 订阅；写入即持久化；撤销用不可变快照栈（50 步）。
- 拖动用 HTML5 drag；`dragend` 后 150ms 内的 click 被忽略，避免拖完误触发展开。
- 样式内联 `<style>`，类前缀 `.kt-`，颜色只用 `--dsw-alias-*` token。
- i18n：`ctx.locale.register(NS, …)` + `ctx.locale.bind(NS)`，全部文案进词典。

   引导语可增删改、恢复默认、刷新后保留，空列表被拒绝。
3. 归类：新建主题、补一条知识、拖拽归入、Shift 关联、顶层投放区、空白拖放无害、

4. 成树：环与关联分开表达、结构检查措辞、树名标签与说明、保存状态、导出说明、

7. 持久化、v1 迁移、坏数据降级、导入、HTML 转义。
8. 多节点与长标题下的自动布局不重叠、入口可用。
9. 配图：选文件 / 拖入 / 粘贴三条入口、替换与移除、刷新保留、非图片文件被拒、
   无图导出 MD + HTML、有图导出 ZIP（tree.md + images/）与 HTML（内嵌图）。

## 10. 已确认的决策（2026-11-05）

1. **载体**：DSH 插件，放本仓库（`knowledge-tree/`）。
2. **归属语义**：一个主归属 + 可选的多个关联；关联是同一张卡的多处引用，不复制、不改主归属。
3. **引导方式**：本地提示题库，不依赖模型。
4. **输出**：树视图 + Markdown + Mermaid + JSON 四件套。
5. **成树后微调**：允许，改完实时重新体检，不锁定只读。
6. **卡片 = 标题 + 内容**，默认收起、点击展开。
7. **归类 = 自动布局白板**：拖动建链，位置由系统排。
8. **自动布局规则**：分层树状排布 + 底部顶层 / 待整理网格。
9. **新建上位主题**：归类阶段提供「＋ 新建主题」，创建即顶层主题。
12. **配图（v3）**：方案 A 落地——每卡一张、自动压缩、data URL 内嵌 localStorage；
    无图导出 MD + HTML，有图导出 ZIP + HTML。
10. **状态表达**：待整理 / 顶层主题 / 已归入上级三态，摘要数字来自真实数据。
13. **删除确认**：所有知识卡片删除（列举卡片、成树节点）都走**同高内联**二次确认，
    不再一键直删，也不弹需要移动鼠标的气泡；确认按钮原位替换删除按钮，不改变卡片高度。
11. **语言**：中文为主；英文翻译是尽力而为，**不作为硬性兼容要求**。
    自定义引导语只存一份单一列表，不按语言分存；界面切到英文时自定义文案原样显示，
    只有「恢复默认」才重建当前语言的内置文案。

## 11. 已知取舍

- 触屏不触发 HTML5 drag；用卡片展开区的「改归属… / 添加关联… / 设为顶层主题」等价操作。
- 白板不做自由摆放，也不做力导向（会漂移）。
- 同级排序用 ↑ / ↓ 按钮，不做拖拽插入位。
- 树形预览只读；改归属统一回到归类白板。
- 阶段切换会重置白板滚动位置（组件卸载），展开 / 折叠状态保留。
- 引导提示是本地可编辑列表（内置 12 条），不接模型追问。
- 配图受 localStorage 约 5MB 限制（压缩后 40–300KB/张，约 15–25 张）；写满时该图不保存并提示，
  文字与结构不受影响。不做标注 / 裁剪 / 多图相册。
- 英文界面是尽力而为的翻译；缺漏或措辞过时不影响中文主流程。

## 12. GitHub 同步第一版（2026-11-07）

- `library.js` 是可独立测试、可嵌入 Client 的 IndexedDB 资料库；locals/remotes/settings/snapshots/meta 独立 stores。旧数据迁移一次性事务，保留所有原键；失败不空树替换。所有本地编辑按 revision CAS 提交。
- `workspace-ui.js` 在原三阶段编辑器外提供本地多树、远端只读并排查看、手动 Push/Pull。远端缓存与本地文档分离；稳定 treeId 不随文档名变化。
- `github-sync.js` 为 Node GitHub REST adapter。commit pinned reads；tree.json 权威、tree.md 生成、图片 content-addressed；单 Git tree/commit 与 non-force ref 更新。双方相对 baseHash 改动则拒绝，没有自动 merge/force。
- `host-service.js` 使用 DSH `connection.fetch.register` 的 `/api/knowledge-tree/*` 精确 POST 路由，继承 owner 认证与 Host/Origin fence；不另起服务器。Token 仅 Host 会话内存或命名环境变量，配置文件不含秘密，错误不泄露远端响应或 Token。
- `build-client.mjs` 将无依赖 library/UI 的测试源码嵌入现有 Client module loader，不依赖 loader 对相对 import 的支持。修改 library/UI 后必须重新 build。
- 本地依旧以自包含 data URL 保存配图（未实现 Blob 拆存）；IndexedDB 容量由浏览器管理。默认无远端请求；主动刷新/查看/Pull/Push 才访问 GitHub。
- 初版只支持已存在的一个仓库与分支、手动同步；不自动创建分支、PR、仓库或定时同步，不实现卡片级冲突裁决与完整三方合并。快照恢复创建无关联新本地副本，原文档不回滚。
- 测试：GitHub mock API 覆盖竞态、原子提交、损坏/超限拒绝与图片往返；真实 Chrome IndexedDB 覆盖迁移/回滚/CAS/缓存；UI hook harness 覆盖 Push 中编辑、Pull 分叉阻止、离线缓存、恢复与多窗口。
